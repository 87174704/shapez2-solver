# Generation Capability Coverage Pilot

Date: 2026-09-15

This pilot contains 5 forward-replayed instances. It is not a corpus expansion and makes no solve-rate claim.

| Target | Track / refinement | Capability exercised |
|---|---|---|
| `hard-main-004` | main / none | catalog half input used as a painted/rotated chunk; multi-stage stack |
| `hard-main-010` | main / B | three-layer blocker scaffold, Crystal generation, lossless column extraction, non-uniform Crystal occupancy, shared refinement occurrence |
| `hard-side-021` | side / none | shared ordinary occurrences, Cutter byproduct reuse, full Pin subassembly, lower/upper composition |
| `hard-side-039` | side / C | one full refinement occurrence partitioned into multiple target components; both Cutter branches reused |
| `hard-side-041` | side / D | one selected occurrence supplies Yk and Yw while the required D ×2 availability bundle remains complete |

All five targets are official Hard targets and all five witnesses replay to exact target equality. The selection was capability-driven; no Solver run or solve outcome was used.

Unsupported items remain visible in `capabilities.json` and the candidate log: Splitter pending throughput success semantics, a general upper/isolated Pin planner, and a general mixed Pin/Crystal gravity planner. The implemented framework exposes Swapper and canonical legal Crystal breakage, but this small pilot did not force either into an instance merely to claim coverage. Arbitrary multi-color fused Crystal generation is also not claimed.
