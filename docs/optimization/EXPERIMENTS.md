## Experiment E-002: numeric operation-output cache keys

- Status: kept.
- Evidence: operation-output cache accounts for roughly 20-22% of cache gets. W5 performs 5,058,406 gets with 99.87% hits and no eviction, constructing about 84.9 million composite-key characters. W2 performs 286,148 gets with 84.25% hits and no eviction.
- Single variable: replace operation-output cache string keys with collision-free safe integers. Keep one flat Map, 75,000-entry FIFO eviction, cache values, canonical input ordering, candidate enumeration, and search semantics unchanged.
- Encoding: let `B = MAX_INTERNED_SHAPES + 1 = 150001`; allocate each operation id one `B^2` interval. Binary keys use `opId*B^2 + a*B + b`, colored unary uses `opId*B^2 + colorCodePoint*B + shapeId`, and other unary uses `opId*B^2 + shapeId`. With operation ids 0-9, the maximum possible key is below 225,003,000,010, far below `Number.MAX_SAFE_INTEGER`.
- Prototype screen: W2 median -16.2% / mean -14.5% over seven alternating fresh processes; W5 single-run -22.6%; all deterministic result fields matched. This is not yet the formal keep decision.
- A baseline: use the post-E-001 ten-run values recorded above. Acceptance requires 10/10 tests, exact W1-W5 signatures/work counters, stable formal B improvement, no meaningful RSS regression, byte-identical solver copies, and clear code.
- Formal B, two warmups and ten runs: W1 median 423.53 ms (-1.9% vs A), W2 799.89 ms (-9.1%), W3 486.80 ms (-8.4%), W4 1,078.87 ms (+5.7% in this non-interleaved batch). Means changed -3.8%, -7.4%, -7.5%, and +5.2% respectively.
- W4 regression audit: ten alternating fresh-process pairs did not reproduce a regression. Plain/numeric medians were 1,124.67/1,037.83 ms (-7.7%); numeric won 8/10 pairs. Similar paired medians improved W1 by 14.1% and W2 by 8.0%. The conflicting batch reflects environmental/order variance, so no W4 improvement larger than “no reliable regression” is claimed.
- Memory: two fresh W2 pairs showed nearly equal max RSS (239.52 vs 239.01 MiB) and post-GC heap. A single W5 pair favored numeric keys by about 17 MiB peak RSS but is insufficient for a strong memory claim.
- Correctness: 10/10 tests and W1-W5 deterministic kind/depth/states/generated/signatures pass; the flat Map, 75k FIFO, canonicalization, and call ordering are unchanged; solver copies are byte-identical.
- Conclusion: keep. The W2/W3 and paired results show material speedup, W4 has no reproducible regression, memory is neutral, and the change removes heavy string allocation without altering search semantics.

## Experiment E-003: equal-score coarse-flow tie-break

- Status: kept.
- Hypothesis: W5 fragmentation is amplified because Splitter preserves the primary score, is enumerated first, and wins existing sequence ties. Preferring coarser flow only when primary scores are exactly equal should keep useful physical-operation states in the cap-100 beam.
- Single variable: for splitting mode only, compare collector entries by existing primary score, then `Σ(count × throughput²) / Σ(count × throughput)`, then existing sequence. No epsilon and no weighted combination with primary similarity.
- Minimum implementation: incrementally maintain throughput-square total from the initial state through Splitter, unary, and binary successors; pass the derived secondary value to the collector. Do not scan/materialize rejected candidate inventories, remove actions, change enumeration/counters, or combine quota/penalty/macro behavior.
- Original correctness gate: P4-02a fixed Split-required cases; collector precedence tests; hand-written square-total formula tests; all exercised oracle paths replay; six fixed high-cap comparison instances have no false negative or depth gap; fixed narrow-beam gap does not worsen; solver copies match. Astra later found that none of these simultaneously enables splitting, performs beam pruning, and exercises E-003 in a required-split decision.
- Performance/quality gate: W1/W2/W4 logical signatures remain exact; W3 solves at primitive depth no greater than 7; W5 must become a deterministic replay-valid solution below 1,000,000 generated candidates and must not merely hit another limit. Record depth, splitting, minimum throughput, binary loss, wall time, CPU, and RSS.
- Keep/revert: keep only if every hard gate passes and standard workloads show no reproducible material regression. Revert on any invalid path, bounded-domain completeness/depth regression, worsened fixed beam fixture, non-splitting signature drift, W5 limit/no-solution, or need to add another heuristic variable.
